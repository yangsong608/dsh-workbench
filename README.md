## 一、为什么是“工作台”而不是“待办清单”

参考应用的 7 张截图指向同一套模型：**任务只有一份数据**，看板 / 清单 / 时间轴 / 日历 / 专注 / 统计只是它的六种投影。

因此插件的核心不是六个页面，而是：

1. 一份任务模型（标题、空间、日期、时段、状态、优先级、标签、分组、子待办、附件、记录）；
2. 一套派生逻辑（今天 / 完成率 / 周趋势 / 连续天数 / 专注分钟）；
3. 一个能持续保存的本地库（不是 localStorage 草稿）。

## 二、功能清单

### 项目门户（1.2）

- **默认落点**：从侧栏「工作台」或底部 dock 的「门户」进入，先看到门户页，而不是任务看板。
- **项目即工作区**：一张项目卡聚合同一个 DSH 工作区下的产品 / Bug 项目 / 测试项目；卡片显示任务、Bug、测试、笔记四项计数与工作区路径，当前范围有高亮与勾选标记。
- **范围切换**：点项目卡（或左侧项目列表）即切换全局项目范围；任务 / 看板 / 清单 / 时间轴 / 四象限 / 日历 / 专注 / 统计 / 门户计数都按它过滤；`全部项目` 与 `未归属`（历史任务）是两张固定卡。
- **功能卡片**：任务清单、看板、日历、统计、专注、Bug 管理、测试、产品设计、记事本、新闻共 10 张；点卡片进入对应页面，并把 Bug 项目 / 测试项目 / 产品 / 笔记本的当前选择对齐到该项目。
- **项目管理**：门户内直接新建项目 / 产品（写产品名、简介、关联工作区，自动建「产品：名称」笔记本），卡片内编辑 / 删除；卡片上的「进入」会先切到该项目的范围再进页面。
- **范围持久化**：所选项目写入设置（`settings.project`），重开面板后恢复。
- **任务归属**：新建 / 详情编辑都可选项目；快速记录默认落到当前项目。

### 任务

- **看板**：下一步 / 进行中 / 等待中三列；卡片显示空间、标题、描述、时间、子待办进度、附件与优先级标记。
- **行动清单**：正在进行 / 接下来 / 等待中 / 已完成四组；顶部快速记录，`Enter` 直接创建。
- **时间轴**：按开始时间排列今天安排；状态胶囊 + 一键完成；底部总数。
- **四象限**：重要且紧急 / 重要不紧急 / 紧急不重要 / 不重要不紧急。
- **作用域**：今天 / 全部；项目过滤（`tasks.project_path`）；空间过滤；全局搜索（`⌘K`）。
- **筛选**：全部 / 高优先级 / 有子待办 / 有附件 / 未排时间。
- **排序**：按时间 / 按优先级 / 按创建 / 按标题。
- **密度**：标准 / 紧凑（持久化）。
- **新建**：标题、备注、项目、空间、日期、起止时间、优先级、标签。
- **复制 / 删除**：删除前确认，删除后自动选中下一条。
- **详情字段编辑**：点击项目、空间、日期、时间、执行状态、优先级、标签、分组即可修改；写入操作记录。
- **子待办**：增删、勾选、独立备注、计划开始 / 完成时间；主视图显示 `1/3` 进度。
- **附件**：文件选择或从剪贴板粘贴图片（当前只保存元数据：名称 / 类型 / 大小）。
- **通知**：今天已完成、等待中、已过期任务三组汇总。

### 计划

- **日历周视图**：7 天 × 小时网格；全天条；事件按空间着色；右侧「今天 N 项安排」。
- **日历月视图**：6 周网格；每天最多 3 条 + “+N 项”；点日期回到周视图。
- **日历年视图**：12 个月缩略图；有任务的日期着色；点月份进入月视图。
- 周 / 月 / 年切换；上一页 / 下一页；跨年正确。

### 专注

- 15 / 25 / 45 / 60 分钟预设 + **自定义 1–180 分钟**。
- 圆环倒计时；开始 / 暂停 / 重置；用 `Date.now()` 计算剩余，切后台不漂移。
- 专注队列：搜索、当前任务置顶、切换当前任务（计时中禁止切换，避免记错任务）。
- 计时结束自动写入一条 `focus_sessions`，累计到今日专注与统计。
- 「沉浸」模式：隐藏队列，专注卡居中放大。

### 统计

- 周期：**本周 / 本月 / 本年**（趋势桶分别为 7 天 / 本月各周 / 12 个月）。
- KPI：实际完成、今日专注、连续完成天数、计划完成率。
- 趋势柱状图 + 空间完成结构（工作 / 学习 / 生活 / 自建空间）。
- 5 张洞察：完成最多的时间桶、已拆步骤任务、等待中任务、今日专注轮次、连续天数。
- 所有数字实时派生，不写死。

### 记事本

- **多笔记本**：一个笔记本可放多篇笔记；左栏顶部选择 / 新建 / 管理笔记本，笔记可随时移动到其他笔记本；删除笔记本时笔记自动移到其他笔记本。
- **两栏布局**：左栏笔记本选择 + 笔记列表（搜索 / 全部 / 收藏 / 标签过滤），右栏标题 + 所属笔记本 + 标签 + 编辑 / 预览。
- **Markdown**：标题、列表、任务清单、引用、代码块、链接、图片；安全转义，链接只放行 http/https。
- **自动保存**：停止输入 650ms 落库，切笔记 / 切视图 / 页面隐藏时立即冲刷；工具栏显示「保存中 / 已保存 / 保存失败」，另有保存按钮与 `⌘S`。
- **整理**：收藏置顶、标签、全文搜索（标题 / 正文 / 标签）、字数统计、更新时间。
- **AI 完善**：编辑器「AI 完善」直接按通用编辑标准完善；「按要求完善」可先输入要求（补异常流程/压缩字数/改文档语气等）。AI 通过 `workbench_note_update` 写回原笔记，保留笔记本、标签与收藏；产品设计笔记同样适用。
- **转为任务**：一键把当前笔记标题 + 正文摘要变成今天的看板任务。
- **另存 Markdown**：把当前笔记写成 `.md` 到「设置 → 笔记保存目录」，文件名取笔记标题，重名自动加 `(2)`。
- **导出 PDF**：同一目录生成 A4 PDF（标题、所属笔记本、标签、正文、代码块、引用），使用本机 Chrome 无头打印；Chrome 不可用时尝试 Electron。
- **导出成功页**：显示文件名与完整路径，提供「打开文件夹」（Finder 中定位文件）、「复制路径」与「完成」。
- **保存目录**：设置里可改，默认本机用户目录（`~`）；支持 `~/子目录` 与相对路径，自动创建并校验可写。
- **预置欢迎笔记**：首次启用写入一篇 Markdown 指南（只播一次，删除后不会重建）。

### Bug 管理

参考 Teambition 的任务卡片看板与统计：

- **多项目**：一个项目关联一个 DSH 工作区（路径从 `workspaces` 服务读取，也可手填）；项目卡片、筛选、新建 / 编辑 / 删除。
- **看板**：待处理 / 进行中 / 待验证 / 已解决四列；卡片显示项目、优先级 P0–P3、严重程度、计划日期、标签、指派人、AI 线程标记。
- **统计**：总数、各状态、今日计划、完成率进度条、严重程度分布。
- **选择**：卡片复选框多选；未选中时点卡片打开详情（单选）；批量操作栏支持提交 / 设置计划 / 清除。
- **按计划提交**：提交计划日期 ≤ 今天且未解决的 Bug；也可先批量设置计划日期。
- **工作区会话修复**：不依赖 Better Sidebar 侧边对话。提交时用 DSH `sessions` 服务在项目关联工作区新建普通会话（`create({ workspaceId })`，未知工作区退回 `{ cwd }`），把 Bug 列表、工作区绝对路径和修复/验证提示词用 `session.prompt(...,'queue')` 直接发出，然后切到该会话——不刷新页面、不回退到当前工作区。失败时提示词留在剪贴板。
- **优化提示词**：要求逐条读代码/复现、根因、最小改动、实际验证；一次一条；禁止改无关文件/依赖/lockfile/git；无法完成置 verify；完成后必须调用 `workbench_bug_update`。
- **自动回写**：Agent 调用 `workbench_bug_update` 工具更新状态与验证记录；看板每 6 秒轮询刷新，卡片 / 详情显示验证结果。
- **安全**：提交前二次确认，提示会启动 Agent 并可能修改工作区文件。

### 灵感（1.6）

独立的「灵感」模块（研发分组），把一句想法炸成一张可继续生长的图：

- **三种输入**：文字（标题 / 正文 / 补充）、截图（粘贴 / 拖入 / 选择，客户端先压到 1600px webp，落盘到 `<工作区>/.dsh-workbench/ideas/<id>/inputs/`）、URL（生成时由 Agent 抓摘要，失败不阻塞）。
- **AI 六方向发散**：用户与场景 / 痛点与机会 / 方案形态 / 技术与可行 / 商业与传播 / 风险与反例，可选「跨界类比」，还可**自定义角度**（每个灵感最多 6 个）；每方向 3–5 条，每条含「为什么成立」，并自动生成 2–3 条跨支关联。
- **节点编辑**：画布右键菜单（改文案 / 加子节点 / 加同级 / 删除 / 发散）与双击改名，所有修改直接落草稿。
- **双引擎图视图**：思维导图用 **mind-elixir 5.15.1**（双击改名、Tab/Enter 加节点、拖拽换父级、撤销重做、折叠），力导图用 **ECharts 6.1.0 graph force**（分类配色、虚线关联、拖拽、缩放、悬停邻接高亮）；两个库都是 vendor 资产，进入视图才加载，主包不变。
- **继续发散**：点任意方向/节点「沿这个方向再发散」，只追加这一支 2–4 条，其他节点坐标与文案不动，自动产生新版本。
- **版本**：AI 每次生成 = 一个不可变版本；手动编辑进草稿（防抖保存），「存档版本」才落版本；版本对比可选任意 A/B 并交换，显示节点与边级差异，可回滚到 A、也可删除（至少保留一个）。
- **导出**：PNG / SVG / JSON / Markdown 大纲，可下载或直接存到项目工作区 `exports/`。
- **Agent 工具**：`workbench_idea_expand`（可分批写入，`final:true` 冻结版本）与 `workbench_idea_progress`（里程碑上报）；提示词契约与 6 方向维度由宿主生成，客户端只负责派发。
- **项目与门户一致**：门户里新建的产品 / Bug / 测试项目会按其工作区路径自动出现在灵感项目下拉里（同路径不重复建）。
- **旧「灵感调研库」已移除**：产品页不再有「灵感」页签与 `workbench_inspiration_publish` 工具，历史数据自动归档为 `product_inspirations_legacy`。

### 产品设计

产品只是项目壳（名称 / 工作区 / 笔记本）；**导图是唯一的结构源**，模块与设计文档都是从它派生的产物。

#### 导图（多图 / 版本 / 双引擎）

- **一个产品多张导图**：每张独立成「图」（如「收银主链路」「移动端」「V2 改版」），互为补充；每张存库并镜像到 `<工作区>/.dsh-workbench/products/<id>/maps/<mapId>.json`。
  - 笔记 / 模块 / Demo 都带 `mapId`；其他页签可用「全部导图 / 单张导图」切换范围。
- **三条来源**：自建空白 / 导入 Markdown 大纲（可选未标记节点默认类型）/ **从灵感选择**（整图或分支子树，映射：方向→模块/业务、点子→功能、问题→需求(待定)、风险→需求(风险标签)，记 `source_ref` 溯源）。
- **双引擎画布**：编辑用 **mind-elixir**（Tab/Enter 加节点、F2 改名、拖拽换父级、折叠、撤销重做），关系用 **ECharts graph force**（分类配色、虚线关联、拖拽、缩放、悬停邻接高亮、跨图引用伪节点）。两者都是 vendor 资产，进入视图才加载。
- **节点模型 v2**：`{v:2, rootId, nodes[], edges[]}`，节点 `kind` 对齐模块四级（root/module/business/feature/requirement），带 `platform` / `status`（采纳·待定·放弃）/ `tags` / `detail`；tree 边表达层级，relate 边表达关联。
- **版本序列**：每张导图独立 `product_map_versions`（上限 50、至少留 1）。可**存档版本**、**A/B 对比**（新增/删除/改名 + 边变化）、**只读预览**、**回滚**（=新建 rollback 版本，历史不丢）、删除。草稿走乐观锁 `draft_rev`，冲突返回 409。
- **跨图引用**：relate 边可指向 `<mapId>:<nodeId>`；卡片显示「引用 N · 被引用 N」；关系图里点击即跳到目标导图并选中节点；删除目标图/节点时双向级联清理。
- **交互细节**：节点搜索（回车定位居中）、选中提示条（避免隐形选中误删）、撤销/重做（Ctrl/⌘+Z）、导出大纲/导出图片、引用检查（列出出入向引用与悬空项）。
- **v1 → v2 迁移**：旧 `mindmap` 自动转图，节点 id 原样保留（笔记/模块引用不悬空），并自动存档一版 `v1 迁移`；`products.mindmap` 继续作为 v1 镜像，旧版本宿主仍可读。

#### 设计流水线（1.11，先文档后模块）

按「**导图 → 业务模块设计文档 → 提炼模块 → 产品设计 → 交叉检查**」的顺序分四步，每步是独立的智能体团队派发，可全跑也可分步跑：

| 阶段 | 做什么 | 产物 |
| --- | --- | --- |
| ① 业务模块设计文档 | 按导图的分组节点（模块/业务）逐个写设计文档；只写导图里的事实，缺的标「待确认」 | `kind=module_design` |
| ② 从文档提炼模块 | **反向**从文档读出「产品→模块→业务→功能/需求」并落库；文档与导图冲突时以导图为基准并注明 | `modules` |
| ③ 产品设计文档 | 只写跨模块内容（信息架构 / 旅程 / 职责矩阵 / 依赖 / 路线图 / 全局约束）；**按模块数建议单份或分册**（≤6 单份，>6 分册），可手动切换 | `kind=product_design` |
| ④ 交叉检查与修复 | 四方比对（导图 ↔ 模块 ↔ 模块文档 ↔ 产品文档），分 A/B/C/D 四类偏差，**一律以导图为事实基准**修复，导图本身不动 | 检查报告 |

- **多导图联合**：面板可多选参与生成的导图，提示词按图分节汇总节点。
- **增量模式**：只处理「节点改动过 / 尚无文档」的部分。
- **分步执行**：一次只跑一步，完成后在笔记页点「继续下一步」；也可以一次跑完全部，但每步都会**等团队真正 done 再进下一阶段**（失败/超时即停）。
- **可观测**：每阶段都有进度条（`product_progress`）+ 页内会话（流式事件、成员/任务投影、停止、重开外部会话）。

#### 模块与设计文档

- **模块**：层级「产品 → 模块 → 业务 → 功能/需求」× 端「PC / 移动 / 平板 / 全部」；可手工新建/编辑（局部更新不冲掉关联）/删除（子项提升为顶层）、按类型与端筛选、树形展示。
- **模块 ↔ 导图节点**：`node_id` 可手动关联，卡片显示「◆ 导图」。
- **设计文档三类**：`module_design`（业务模块设计）/ `product_design`（产品设计，可分册）/ `feature_design`（按功能节点）；卡片有类型徽标，笔记页顶部有分组统计。
- **幂等**：文档按 `doc_key` 唯一（`md:<模块>` / `pd:<产品>[:<模块>]` / `fd:<图>:<节点>`），**AI 重跑 = 更新同一篇**，不会堆重复文档。
- **覆盖度**：笔记页顶部显示「覆盖 X/N 个节点」，节点胶囊（绿点=已写），可一键「勾选缺失」。
- **就地编辑**：点卡片直接开编辑弹窗（标题/正文/关联节点），不跳走；支持手工新建（默认归到产品笔记本 + 当前导图）与删除（同步删 `.md` 镜像）。

#### 归档

产品 / 模块 / 设计文档统一 `archived_at`：列表默认隐藏，工具栏「显示已归档」可查看；归档后显示 ↩ 可恢复。删除与归档分离——归档只是收起，不删数据。

#### 产品 Demo

- **双通道**：「快速渲染」本地模板 + 设计笔记即时出稿（零额外额度）；「AI 深度生成」由工作区会话产出高保真可交互原型（≥3 类交互）。支持单页面 / 产品系统（多页），目标端自适应 / PC / 移动 / 平板。
- **12 套分端 UI 主题**：通用（极简白 / 玻璃拟态★ / 新拟态）、PC（编辑杂志 / 暗色仪表盘★ / Bento 网格★ / 科技终端）、移动（流光渐变★ / 温暖奶油★ / 黏土拟态 / 新粗野）、平板（平板双栏）；每套绑定设计令牌（进提示词）+ 本地 CSS。
- **进度与预览**：`product_demo_progress` 进度卡；工作台内 iframe 预览，PC / 平板 834px / 移动 390px 视口切换。

### 统一研发域（1.0）

- 层级：**产品 → 模块 → 业务 → 功能 / 需求**；端：**PC / 移动 / 平板 / 全部**。
- 产品「模块」页：AI 按导图拆分模块/业务/功能/需求，调用 `workbench_module_publish`；每个模块用 `workbench_product_note_publish` 生成详细设计笔记（moduleId/platform 关联）。
- Bug：新增 `platform`/`moduleId`；表单可选端；测试失败录入 Bug 自动带端/模块。
- 测试项目/用例：带 `platform`/`moduleId`；AI 用例提示词包含默认端与模块。
- **AI 协同**：产品/测试/Bug/笔记提供「AI 协同」；可选择**新建工作区会话**或**追加到已有会话**（下拉标注会话所属工作区）。新建走 `sessions.create({ workspaceId | cwd })` + `session.prompt(...,'queue')`，追加走 `retainAgentScope` + `prompt(...,'queue')`，两条通道都不刷新页面；Bug 提交后立即回写 `aiThreadId` 与 `doing` 状态。
- 执行页新增实时 3D 用例塔、扫描光束、通过率环；报告 3D 柱状/环/时间线保留，尊重 reduced-motion。
- 数据迁移在宿主启动时执行；旧 products/bugs/tests 数据保留，模块/端默认 all。

### 测试

- **测试项目**：多项目；关联 DSH 工作区；项目/用例/运行 JSON 与报告保存到 `<工作区>/.dsh-workbench/tests/<projectId>/`；自动创建「测试：名称」Bug 项目。
- **AI 用例生成**：三种来源——手写需求、产品设计笔记、产品 Demo + 笔记。新会话 + `workbench_testcase_publish` 逐条写入；覆盖正例/反例/边界/异常/权限/回归。
- **执行**：按用例逐条标记通过/失败/阻塞，填写实际结果；运行汇总与状态自动计算。
- **Bug 闭环**：失败用例「录 Bug」自动写入 Bug 管理（含前置/步骤/预期/实际/优先级），结果保留 Bug id。
- **回归**：一键把失败/阻塞用例带入新运行；回归通过后自动把关联 Bug 置 `verify`，继续用 Bug 管理完成 resolved。
- **动画报告**：2D KPI + CSS 3D 等距柱状（逐条生长）+ 通过率环 + 时间线；可保存自包含 HTML 到工作区 `reports/`。
- **Docker 部署**：本机或 SSH 服务器；配置镜像/容器/端口/远端目录，宿主执行 `docker build → rm -f → run -d -p` 并回传日志。Docker 未启动/未配置时会明确失败，不影响用例与报告。

### 定时新闻

- **订阅**：主题名称 + 检索关键词 + 频率（每天 / 工作日 / 每周 / 自定义 cron）+ 多个检索时间 + 每次检索条数（3–20 条）。
- **预置主题**：AI 行业动态 / 科技产品 / 财经市场 / 国际时事 / 健康生活 / 体育赛事 / 游戏动漫 / 开源项目，点一下填入标题与关键词。
- **AI 总结**：Agent 为每条新闻生成 100–180 字总结（事件、关键数据、影响），卡片正文展示；标题下保留来源与日期。
- **定时执行**：每个时间在 **@goodandready/dsh-cron** 创建一个 `llm` 任务；到点由 DSH Agent 用网页搜索检索，再通过 `workbench_news_publish` 工具把结果写回工作台。
- **展示**：订阅卡（状态 / 频率 / 条数 / 下次运行 / 上次入库）+ 小红书式瀑布流新闻卡片；卡片高度随 AI 总结长度变化，3 列（窄屏 2/1 列），按主题筛选、立即检索、暂停 / 恢复、编辑 / 删除。
- **去重**：服务端按 URL 哈希去重；同一订阅最多保留 200 条。
- **成本可见**：订阅弹窗明确提示会消耗模型额度；任务权限固定为只读。
- **刷新**：进入新闻页、手动刷新、以及页面打开时每 25 秒轮询一次；触发检索后 4 分钟内每 6 秒轮询。

### 全局

- 主题：跟随 DSH / 浅色 / 深色。
- **侧栏入口**：克隆 DSH 原生「新建会话」按钮，紧跟在「定时任务」后面，尺寸 / 图标 / 文字 / 收起行为与定时任务完全一致（不再占用面板列表里的小图标位）。
- 面板内侧栏自动收起（宽度 < 1250px），顶栏按钮展开；窗口 / DSH 侧栏尺寸变化会自适应，手动切换后保持手动选择。
- `⌘K` / `Ctrl+K` 聚焦搜索；`Esc` 关闭弹窗；字段行支持 `Enter` 打开编辑器。
- 自动保存状态（保存中 / 已自动保存 / 保存失败）；外部修改冲突时自动重载并提示。
- 导入 / 导出 JSON；数据存储健康信息（引擎、SQLite 版本、revision、条目数）。

## 三、主题适配（MOSS / opencode-palette）

### 机制

工作台不写死一套“深色”。CSS 变量默认映射到 DSH 主题服务注入的 `--dsw-alias-*` token：

| 工作台变量 | DSH token | 用途 |
| --- | --- | --- |
| `--bg` | `--dsw-alias-bg-base` | 页面底 |
| `--panel` / `--panel-2` / `--panel-3` | `--dsw-alias-bg-layer-1/2/3` | 面板、卡片、胶囊 |
| `--line` / `--line-strong` | `--dsw-alias-border-l1/l2` | 发丝线 |
| `--text` / `--text-2` / `--text-3` | `--dsw-alias-label-primary/secondary/tertiary` | 三级文字 |
| `--accent` / `--accent-ink` | `--dsw-alias-brand-primary/brand-text` | 主色、选中、进度 |
| `--green` / `--amber` / `--red` | `--dsw-alias-state-success/warn/error-primary` | 状态色 |
| `--accent-soft` 等柔和底 | `color-mix(token, var(--panel))` | 选中底、提示底 |

因为 Shadow DOM 会继承宿主 CSS 变量，MOSS 在任意祖先节点（`html` / `body` / 壳层）切换 token 时，工作台**无需重挂载**即可跟着变色。

### 三种主题模式

| 模式 | 行为 |
| --- | --- |
| **跟随 DSH**（默认） | 完全使用 `--dsw-alias-*`；MOSS 550W 深红、MOSS 浅色暖纸、opencode 38 套皮肤都自动同步 |
| **浅色** | 固定使用工作台自带浅色（`data-wb-theme="light"`），不受宿主皮肤影响 |
| **深色** | 固定使用工作台自带深色（`data-wb-theme="dark"`） |

顶栏主题按钮 / 设置页均可切换；默认 `auto`，设置持久化在 SQLite 的 `settings.theme`。

### 实测

- **dsh-startup-moss**：当前运行在 550W 深红主题，工作台自动取到 `#0b0605 / #120908 / #ff3b2f`，按钮、进度环、选中态、卡片全部同步（见截图 01–04）。
- **dsh-opencode-palette**：使用同一套 token；为不改动当前皮肤，用 Tokyo Night token（`#1a1b26 / #7aa2f7 / #c0caf5`）注入祖先节点做等效验证，工作台即时切换为冷蓝紫色。
- 切回 `auto` 后 token 立即恢复；显式浅色 / 深色也验证过。

## 六、数据与接口

### 存储

- 主库：`~/.dsh/dsh-workbench.sqlite`（WAL、外键、`synchronous=NORMAL`）。
- 可用环境变量 `DSH_WORKBENCH_DB` 指定别的路径。
- 若运行环境没有 `node:sqlite`，自动降级为同目录 `dsh-workbench.json`，接口与行为不变。

### 表

| 表 | 内容 |
| --- | --- |
| `spaces` | 空间（工作 / 学习 / 生活 / 自建），名称、颜色、排序 |
| `tasks` | 任务主表：标题、描述、备注、空间、项目（`project_path`，DSH 工作区绝对路径，空串=未归属）、状态、优先级、日期、起止、时长、标签、分组、完成时间 |
| `subtasks` | 子待办：标题、完成、计划起止、独立备注、排序 |
| `attachments` | 附件元数据：名称、类型、大小 |
| `logs` | 操作记录：创建、改字段、完成、专注等 |
| `focus_sessions` | 专注记录：任务、开始时间、分钟、是否完成 |
| `settings` | 主题、密度等键值 |
| `news_topics` | 新闻订阅：主题、关键词、频率、时间、每次条数、cron 任务 id、启用状态、上次入库 |
| `news_items` | 新闻条目：标题、URL、来源、发布时间、一句话摘要、AI 总结、入库时间、URL 哈希（唯一） |
| `notebooks` | 笔记本：名称、创建/更新时间 |
| `notes` | 记事本：所属笔记本、标题、Markdown 正文、标签、收藏、工作区文件路径、创建/更新时间 |
| `modules` | 产品模块/业务/功能/需求：父级、kind、platform、noteId、状态 |
| `test_projects` | 测试项目：名称、工作区、产品、模块、端、Bug 项目、Docker 部署配置 |
| `test_cases` | 测试用例：项目、标题、前置、步骤 JSON、预期、优先级、类型、来源 |
| `test_runs` | 测试运行：项目、状态、结果 JSON、汇总、部署日志、时间 |
| `products` | 产品：名称、简介、工作区、产品笔记本、导图 JSON、风格 |
| `product_demos` | 产品 Demo：产品、风格、范围、功能 id、标题、HTML 文件路径 |
| `bug_projects` | Bug 项目：名称、关联工作区路径 / 名称、创建/更新时间 |
| `bugs` | Bug：项目、编号、标题、描述、状态、严重程度、优先级、计划日期、标签、验证记录、AI 线程、指派人 |
| `meta` | schema / revision / seeded 标记 |

写入采用**整份快照 + 事务**：单用户本地数据量小，语义简单，永远不会出现半写状态。每次写入 `revision + 1`。

| POST | `/workbench-api/products/mindmap` | `{productId, mindmap}` 保存导图并写工作区 JSON |
| POST | `/workbench-api/products/demo` | `{productId, scope, style, featureId, title, html}` 保存 Demo 到工作区 |
| GET | `/workbench-api/products/demo?id=` | 返回 Demo HTML（iframe 预览） |
| GET | `/workbench-api/tests` | 返回 `{projects,cases,runs}` |
| POST | `/workbench-api/tests/projects` | 新建/编辑测试项目（自动建 Bug 项目） |
| DELETE | `/workbench-api/tests/projects/:id` | 删除测试项目及用例/运行 |
| POST | `/workbench-api/tests/cases` | 新建/编辑用例 |
| DELETE | `/workbench-api/tests/cases/:id` | 删除用例 |
| POST | `/workbench-api/tests/runs` | 新建/更新运行（结果/汇总/状态） |
| DELETE | `/workbench-api/tests/runs/:id` | 删除运行 |
| POST | `/workbench-api/tests/report` | 保存自包含报告 HTML 到工作区 |
| POST | `/workbench-api/tests/deploy` | Docker 部署（本机或 SSH），返回日志 |
| POST | `/workbench-api/bugs/status` | 回归通过后更新 Bug 状态 |
| POST | `/workbench-api/notes/reveal` | `{path}` 在系统文件管理器中定位导出文件（限制在当前保存目录内） |

新闻定时任务使用 dsh-cron 的官方同源接口：`GET/POST /dsh-cron/tasks`、`POST /dsh-cron/tasks/:id/run|pause|resume`、`DELETE /dsh-cron/tasks/:id`。工作台不直接操作 cron 的存储。

**冲突处理**：浏览器半侧保存前带上 `revision`；409 时丢弃本地待写快照、载入服务端状态并提示“数据已在别处更新，已重新载入”。

**Agent 工具**：宿主半侧注册 `workbench_news_publish`，参数 `{ topicId, items:[{title,url,source,publishedAt,summary,aiSummary}] }`。它只做校验、URL 协议过滤、按 URL 去重与落库，并按订阅的「每次条数」截断；定时任务的提示词会显式要求 Agent 在完成后调用它（没有新闻时传空数组）。

**笔记工具**：`workbench_note_update`，参数 `{noteId, title?, content}`。AI 完善后调用它；保留所属笔记本、标签、收藏，并同步工作区 Markdown。

**统一域工具**：`workbench_module_publish`（productId/parentId/name/kind/platform/description）。

**测试工具**：`workbench_testcase_publish`，参数 `{projectId,title,precondition,steps[],expected,priority,type,source}`；AI 按用例逐条调用。

**产品工具**：`workbench_product_note_publish`（写设计笔记，走现有 notes）、`workbench_product_demo_publish`（供外部 Agent 写 Demo；工作台 UI 默认用本地渲染器）。

**Bug 工具**：`workbench_bug_update`，参数 `{bugId, status:'open'|'doing'|'verify'|'resolved', verification?, note?}`。工作区会话里的 AI 修复并验证后调用它；不传 `verification` 时保留原验证记录，`note` 会追加到验证记录。

**备份 / 恢复**：设置 → 导出 JSON；导入 JSON 会整份覆盖（导入前建议先导出）。新闻 / 笔记 / Bug 数据不在任务快照里，需要时直接用 SQLite 工具备份整个 `.sqlite` 文件。

## 十、已知边界

1. **附件只存元数据**：文件名 / 类型 / 大小；不保存文件内容，也没有缩略图。图片粘贴与文件选择走同一套元数据入口。
2. 不支持拖拽排序、列间拖动、重复任务、提醒、多人同步、跨设备。
3. 专注计时依赖前端时间戳；关闭 DSH 会停止未完成的计时，不写未完成记录。
4. 日历年视图是 12 个月缩略图，不是逐日大图。
5. 接口未额外加鉴权，依赖本机回环访问；多人 / 公网暴露前需要补鉴权。
6. 冲突处理是“服务端优先”，本地未保存修改会被丢弃（会提示）；不做字段级合并。
7. 首次启动播种 10 条示例任务；删除后不会再次播种（`meta.seeded` 已置位）。
8. 新闻检索依赖 **@goodandready/dsh-cron** 与 DSH Agent 的网页搜索能力；cron 不可用时订阅仍可展示，但不能创建/运行任务。
9. 新闻是模型检索与摘要结果，不保证覆盖全部来源；URL 已校验 http/https 并去重，但内容仍需自行核实。
10. 每次检索会消耗模型额度（实测一次约 0.02–0.04 美元、40–90 秒；条数越多 / 总结越长越贵）；示例订阅默认先保持暂停，确认后再恢复。
11. 瀑布流使用 CSS columns，卡片按列自上而下排布（不是严格的横向优先 masonry）；同屏高度差来自 AI 总结长度与来源。
12. 旧新闻若没有 `aiSummary`，卡片回退显示一句话摘要（标记「摘要」）；只有新检索会补 AI 总结。
13. 「工作台」入口按定时任务样式克隆到侧栏，不再作为面板列表条目出现；如果你的「工作台门户」需要把它列为卡片，需要另加隐藏注册。
14. 记事本 v1 不包含 Git 同步、`@` 引用、对话一键记入、图片上传；Markdown 预览是轻量自研渲染器（覆盖常用语法，不追求 GFM 全量）。
15. 设置里的 JSON 导出目前仍只导任务快照；笔记/新闻/笔记本在同一个 SQLite 文件里，完整备份请复制 `~/.dsh/dsh-workbench.sqlite`。
16. PDF 依赖本机 Chrome 无头打印；没有 Chrome 时回退 Electron。PDF 目录必须可写，默认用户目录，导出不会覆盖同名文件（自动加 `(2)`）。
17. 「另存 / PDF」直接写入设置里的目录，不弹系统保存对话框；需要每次选路径时请先改目录。
18. 「打开文件夹」只允许当前保存目录内的路径；通过 Finder / 资源管理器定位，不在目录内会拒绝。
19. AI 会话提交全部走 DSH `sessions` 服务（新建 / 追加），不再刷新页面，也不再依赖侧栏按钮与输入框 DOM；旧版 `sessionStorage` 待发送队列已移除。

## 十一、排障

| 现象 | 处理 |
| --- | --- |
| 侧栏没有「工作台」 | 重启 DSH；确认 `~/.dsh/profiles/desktop/package.json` 的 bundles 含 `dsh-workbench` |
| 面板空白 / 一直“正在读取工作台” | 打开 `http://127.0.0.1:<port>/workbench-api/health` 看宿主是否就绪；看 DSH 日志中 `[dsh-workbench]` |
| 提示“保存失败” | 检查 SQLite 文件权限 / 磁盘空间；看 Network 中接口返回 |
| 提示“数据已在别处更新” | 正常冲突保护：重新载入服务端状态；重新操作即可 |
| 颜色不像当前皮肤 | 主题设为「跟随 DSH」；确认 MOSS / opencode palette 已启用 |
| 新闻页提示未检测到 `/dsh-cron/tasks` | 安装 / 启用 `@goodandready/dsh-cron`，重启 DSH；到「插件」页确认 Cron 已启用 |
| 点了「检索」一直没结果 | 在「定时任务」面板看该任务运行日志；模型可能未调用工具或搜索失败；4 分钟后状态自动回退 |
| 新闻订阅任务重复/残留 | 工作台删除订阅会同时删除对应 cron 任务；若手动在 cron 面板删过，重新保存订阅即可重建 |
| 忘记数据在哪 | `~/.dsh/dsh-workbench.sqlite`，可用任意 SQLite 工具打开 |
