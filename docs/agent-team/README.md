## 核心结论

1. **调度不自研**：DSH 已内置实验性 Agent Teams（roster / inbox / 任务 DAG / CAS / 投影 / 等待与中断），工作台做"团队模板 + 派发 + 呈现"。
2. **页内会话 = 会话投影 + 输入通道**：读 `session/event` 流式渲染，写走 `sessions.prompt`，不造第二套消息系统。
3. **异常模型**：借鉴 PixOffice 的状态码语义（202/408/409/410）与 WorkBuddy 的显式终态（failed/timeout/cancelled），把超时做成状态而不是异常。
4. **记忆分层**：个人 / 项目 / 团队 / 会话，默认手动确认写入；知识系统先做 SQLite FTS5，不引入向量库。
5. **风险最高的是页内会话的工程闭环**（S1–S4），建议先做 Spike 再排期。

## 已定决策（2026-10-23）

1. 页内会话：**右侧抽屉 320–560，可拖宽**（窄屏自动底部分栏）
2. 默认团队：**7 人全启用**（并发 3、15 分钟预算兜底）
3. 文件权限：**默认按角色，运行时可改**（运行中不可热改：下次派发生效，或创建替代成员）
4. 记忆写入：**手动确认**（建议记忆卡片），v1 不自动写
5. 可视化：**v1 不做 2D**，只做团队/任务卡片与状态
